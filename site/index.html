Colour · critique · a buildable library

A design forge
that shows its work.

Hephaestus turns a plain-language brief into a working palette, tells you which of its rules the palette breaks and why, and keeps a library of 1,750 design directions you can build from rather than admire. Every answer comes from its own arithmetic — nothing is generated for you by a model, so the same brief gives the same answer tomorrow, and you can look up how it was reached.

    Earlier releases

      What it does

      § 02 — the tool, not the idea

      Six screens, one document model, and an export that produces a real site rather than a picture of one.

      Akmon the palette forge

      Type a brief — “deep dusty teal with a burnt orange accent, dark” — and it returns surfaces and voice as two labelled grids: background, surface, border, text, muted, then primary, secondary, accent. Every swatch is editable in place, click-copies its hex, can be locked before a re-forge, and carries its measured contrast grade. There is a colour-blindness check and a lightness ramp, because a palette that only works for one pair of eyes is not a palette.

      Cedalion the critic

      It reads a palette or a page and says what is measurably wrong: which rule fired, what number it looked at, what it would change. No vibes, no “consider exploring”. It runs the same checks the forge uses to build, so a pass means something. A pass can also say nothing — an empty critique is the correct result for a design that is fine.

      The catalogue 1,750 directions

      Twenty-one hand-written 2026 trend records, decomposed into layout and accent atoms and crossed with twelve registers — Atrium, Ledger, Foundry, Vitrine, Signal, Marginalia, Atelier, Kiosk, Corridor, Console, Nook, Archive. 1,390 combinations are refused because their atoms fight each other. Each surviving entry carries numbers to score against, a drawn example generated from those numbers, and a recipe naming the exact blocks and options to use.

      Studio & canvas build it here

      A free canvas with blocks you can select, drag and resize; a grid library of 17 ready section layouts; twelve site options (typeface, text size, corners, card depth, image fill, motion, airiness, heading case and tracking, button shape, card outline and more) that are honoured by the editor and by the export. The preview button opens the exported site itself, not a mock of it.

      Merkhet measure, repair, re-measure

      It audits the page you are building, fixes what it can, then measures again and reports how many problems went away, what is still open, and what it tried and put back because the result read worse. No tick for a fix it hasn't verified — that is the whole reason it is worth running.

      Export files you own

      Static HTML and CSS for a site, plus a token file for a design system: radius, spacing, type scale, the colour roles. There is no proprietary project format to be trapped in; the app's own state is one JSON file on your disk, and the six shell themes (Obsidian, Graphite, Paper, Claude, Blueprint, Ember) are a preference, not a licence tier.

      How it thinks

      § 03 — arithmetic, on purpose

      The design tool market has settled on “ask it to make something”. Hephaestus is deliberately the other kind of tool, and the trade-offs are real in both directions.

      • Colour science, not adjectivesEverything runs through OKLab: lightness, chroma, hue distance, contrast. The critique engine's threshold is the point where a human reliably notices a difference, so “too close” is a measurement rather than an opinion. A palette is judged on numbers you could recompute yourself.
      • Rules that name themselvesA verdict arrives with the rule that produced it and the value it checked. When a rule is wrong for your work, you can see that it fired and why — which is the only way to disagree with a tool usefully.
      • Deterministic, so reproducibleThe same brief gives the same palette next month. That is what makes a saved palette reviewable later, and what makes the exported site match what you approved. Randomness exists in one place — a seeded re-forge, seeded from the words you typed — so re-rolling is a choice you made, not noise that happened.
      • Combinatorics instead of a modelThe 1,750-entry library is composed from atoms and a compatibility matrix, not sampled from a language model. That is why it can refuse 1,390 combinations with a reason, and why nothing needs a network, a key or a quota.
      • What that costs youIt will not write your copy, invent a brand, or produce forty variations while you wait. It is a forge: good at colour, structure and judgment, silent about everything else.

      The catch

      § 04 — worth reading first
      • No AI, anywhereNothing sends your work away to be generated for you. Some people will find that limiting; it is the point.
      • No account, no telemetry, no networkThe app runs offline and keeps its files on your disk. This page makes exactly one request of its own: a same-origin read of release.json, to find out what is published. No fonts, no images, no analytics, no cookies, nothing that could count you reading it.
      • Free, and not “free during beta”MIT licence. No key, no seat count, no license screen, nothing that stops working in a year.
      • 0.x, and single-maintainerIt is one person's tool, version 0.3.0. Expect rough edges and no support desk; expect the changelog to be honest about what is unfinished.
      • Not a Figma replacementNo multiplayer, no plugin API, no prototyping. It is strong at colour, critique and a buildable direction library, and quiet about everything else.
      • Unsigned macOS buildsOne right-click at first launch. The reason is money, not care: there is no Apple Developer ID in this project, and the signing field of release.json says so in words rather than hiding it.
      • Manual updates, for nowThere is no in-app updater, because a real one needs a signing key that does not exist here. Downloading the new file is the update path, and this page is where it appears.

      How a release gets here. Four build machines produce the installers; a final job checks that every platform's file exists, is a plausible size, and carries the version the project's config files agree on; the survivors are copied into downloads/ next to this page and release.json is rewritten with their paths, byte counts and sha256 sums. The site is deployed only after that check passes, and a partial or failed build leaves the live release exactly as it was. There is no step where anyone edits this page to ship a version — which is why nothing on it can be stale.
